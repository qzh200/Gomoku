# AlphaZero 引擎设计（az）

**状态**：已实现（`az_worker/`），权重需要自己训练
**范围**：新增 `az_worker/`，不改变 Worker 协议、REST 契约与 Go 侧代码
**兼容目标**：`AlphaZeroEngine.choose_move(board, history, player, last_move, config)`
与 `AZ_MODEL_PATH` / `AZ_SIMULATIONS` / `AZ_C_PUCT` / `AZ_DEVICE` 可用
**操作手册**：[`az-training.md`](az-training.md)（预热 → 自对弈 → 擂台赛）

## 0. 摘要

传统引擎是「评估函数 + 搜索」：棋型表给出分，搜索在树上找最好的分支。AlphaZero
换掉了这两样东西：

1. **策略网络**：给棋盘上每一个格子打分，输出「下一步下哪里」的概率分布；
2. **价值网络**：给整个局面打分，输出「这盘谁占优」，范围 −1 到 1；
3. **MCTS（PUCT）**：用策略当先验、用价值当结果，在自己跟自己对弈产生的数据上训练。

没有手写棋型、没有手写估值、没有启发式剪枝。棋力来自两件事：网络的质量，和搜索的深度。
代价是必须先训练，而且训练要吃显卡。

```
az_worker/
  board.py      棋盘：落子、撤销、成五判定、候选点
  features.py   局面 → 三个 15×15 平面；八种对称
  network.py    ResNet 骨干 + 策略头 + 价值头；训练与推理
  mcts.py       PUCT 搜索：选择、展开、评估、回传
  engine.py     choose_move：协议入口
  selfplay.py   自对弈：产生训练样本，训练
  train.py      训练命令行
  arena.py      擂台赛：AlphaZero 对传统引擎
```

## 1. 目标与非目标

| 指标 | 目标 |
| --- | --- |
| 对传统引擎胜率（100 局，换色） | 训练后 ≥ 50% |
| 单手时间 | 由 `AZ_SIMULATIONS` 控制，默认 400 次模拟 |
| 成五 / 堵五 | 100% 直判，不交给网络 |
| 训练硬件 | 单张消费级显卡（本机 RTX 4060 8GB） |
| 非法落子 / 超时崩 | 0 |

非目标：禁手规则、跨机分布式训练、对手搜索（AlphaZero Zero）、开局库。

## 2. 局面表示

网络不看格子编号，只看三个 15×15 的 0/1 平面：

| 平面 | 内容 |
| --- | --- |
| 0 | **自己**的棋子（永远是轮到走棋的一方） |
| 1 | **对手**的棋子 |
| 2 | **上一手**落在哪个格子 |

所有平面都相对「轮到走棋的一方」编码，所以同一盘棋换边不用改网络——这正是
AlphaZero 原始设计里把棋盘编码成「自己的子 / 对手的子」的原因：黑白互换时输入
分布不变，训练数据直接翻倍。

**上一手平面**是本设计相对原版 AlphaZero 的改动。五子棋的威胁依赖「刚刚落子在
哪」，尤其是双活三、冲四这类需要看清上一手才判断得出的棋型。少了这一层，网络
要重新从棋盘上把「哪颗子是新的」推出来，浪费容量。

### 对称性

15×15 是正方形，有 8 种对称（4 种旋转 × 翻转）。`features.TRANSFORMS` 给出每种
对称的格子映射，训练时随机挑一种，把平面和策略向量一起变换。棋局的价值不变，
所以同一个样本能贡献 8 份数据。

## 3. 网络

```
输入 3×15×15
  ↓ stem: 3×3 卷积 (64 通道) + BN + ReLU
  ↓ 6 × 残差块（每块两层 3×3 卷积 + BN + 捷径）
  ├─ 策略头: 1×1 卷积 → 2 通道 → FC → 225
  └─ 价值头: 1×1 卷积 → 1 通道 → FC(64) → FC(64) → FC(1) → tanh
```

- **策略头**输出 225 个 logits（每个格子一个），非法格子（已占、离棋太远）在
  softmax 之前被压到很小的值。实际实现用 `-1e9` 而不是 `-inf`：`-inf` 会让
  `log_softmax` 产生 NaN 的梯度。
- **价值头**输出 `tanh`，范围 [−1, 1]，从**轮到走棋的一方**看。
- 通道数 64、残差块 6 是个起点；`--channels` / `--blocks` 可以调。8GB 显存的卡
  上 batch 64 没问题。

## 4. MCTS（PUCT）

每个节点存：访问次数 `visits`、价值和 `value_sum`、先验 `prior`、子节点表。

选择子节点用 PUCT：

```
score(child) = Q(child) + c_puct × P(child) × √(总访问) / (1 + child.visits)
Q(child)     = −value_sum(child) / visits(child)
```

`Q` 取负号，是因为节点的价值是**站在该节点轮到走棋的一方**看的，而父节点要的是
自己这一边的评价，两者视角相反。

### 4.1 搜索流程

```
root = 新节点（局面 + 上一手）
用网络评估 root → 先验 → 展开成子节点（每个合法着法一个）

重复 N 次：
  1. 从 root 往下选：PUCT 分数最高的子节点
     - 走到没有子节点的节点 → 它是一个叶子，加入待评估批次
     - 走到已经终局的节点 → 直接回传胜率
  2. 待评估的叶子攒够一批（或整批都等齐了）→ 一次前向 → 展开 → 回传
  3. 回传时每上一层符号取反
```

### 4.2 批处理与虚拟访问

叶子在网络上评估之前，它的访问次数还没加上。同一批里如果两次下到同一个叶子，
它的估值就被算了两遍。所以：

- 待评估的叶子记在 `waiting` 集合里，**选择阶段直接跳过**；
- 走到某个节点时它的所有子节点都在 `waiting` 里时，先把整批评估掉，再继续。

这样一批里不会有重复叶子，GPU 一次能吃到 32～64 个局面。

### 4.3 候选点半径

候选点是「离某颗棋子半径 N 以内的空点」。半径 1 是默认：

| 半径 | 候选点数 | 访问分布的熵 | 前三名的访问数 |
| --- | --- | --- | --- |
| 1 | 20 | 1.02 | 284 / 81 / 5 |
| 2 | 46 | 1.48 | 278 / 47 / 7 |

（400 次模拟，同一局面。熵越低，分布越尖。）

半径 2 让搜索的访问次数摊到更多候选点上，策略头拿到的目标分布就更平，学到的
东西更少。传统引擎也有同样的结论（`docs/classical-engine-v2.md`：半径 1 而不是 2）。

### 4.4 终局

成五的判定在**展开子节点时**做，不在网络里：落子后如果连成五，子节点的终局值
直接是 −1（对轮到走棋的一方而言，他输了）。因此：

- 搜索不会「看漏」一个已经成五的局面；
- 但网络**不会**因为训练不足而漏掉「再下一手就成五」——那仍然要靠网络。

## 5. 兜底规则

搜索之前先做两条硬判定（`engine._forced_move`）：

1. 自己能成五 → 直接落；
2. 对手有成五点 → 堵它。

这两条不依赖网络，所以训练不足的网络也不会白送一局。除此之外的一切都交给搜索。

> 对手有**两个**成五点时已经无法防守：一个活四的两端都能成五，双四也是两个点，
> 一步只能堵一个。传统引擎对这种情况的约定也是一样的（`classical_worker/threats.py`
> 的 `forced_moves`：「faces two fives is lost … 把堵法作为最不坏的着法返回」）。
> AlphaZero 这边也照这个约定走：照样堵一手，不把棋随手扔掉。至于「两个五点时
> 还能不能反杀」，没有特判，靠网络的价值头自己学会。

## 6. 启动问题：预热

纯自对弈有个绕不开的坑：**网络必须先学会基本棋型，价值头才有话说**。价值头说
不出话，搜索的访问次数就平摊在所有候选点上，策略头拿到的训练目标是一份近似
均匀的分布，于是网络学不到任何东西——鸡生蛋。

实测（本机 RTX 4060）：

| 阶段 | 策略验证损失 | 价值验证损失 | 对传统引擎 |
| --- | --- | --- | --- |
| 纯自对弈 240 局 | 4.2（几乎没降） | 0.01（背下来了） | 0 胜 8 负 |
| 加预热后 | 0.16 | 0.01 | 见第 9 节 |

「价值损失 0.01」是危险信号：训练集上完美、验证集上 2.17。网络把整局结果背下来
了，而不是学会评估局面。

因此加了一步**预热**（`az_worker/warmstart.py`）：传统引擎当老师。

```
传统引擎自己下棋 → 每个局面记一个样本
  策略目标 = 传统引擎排名的着法（第一名权重 1，之后按 e^(-i/2) 衰减）
  价值目标 = 整局结果（从该局面轮到走棋的一方看：胜 1、负 −1）
```

两者与自对弈的含义一致：策略是着法分布，价值是这一盘对走棋方的预期结果。

**价值目标必须是整局结果，不能是传统引擎的评估分**。这是实测踩到的坑：预热阶段
教价值头 `tanh(传统引擎评估分 / 8000)`，自对弈阶段教它整局结果（±1）。两个阶段
教的是**不同的东西**，切换时价值头的标定整个坏掉：

| 轮次 | 训练价值损失 | 验证价值损失 |
| --- | --- | --- |
| 1（刚切换） | 0.25 | 0.25 |
| 2 | 0.20 | **2.01** |
| 3 | 0.25 | **2.54** |

价值损失从 0.25 跳到 2.5，网络在切换后**比一开始还差**。所以预热也用整局结果
（`--value-target outcome`，默认），两个阶段教同一个东西，切换就没有断层。
`--value-target eval` 保留着，但要知道它的代价。

**软目标比单点目标好**。传统引擎搜出来的那一手是 one-hot，但它的排序里还有
「几乎一样好」的着法。把排序变成一个衰减的分布，网络学到的不只是「第一手」，
还有「第二手也不错」。

**对称增强在这里是必须的**。预热的数据量只有几千个样本，而网络有两百万个参数，
不做增强就是死记硬背：训练损失 0.16，验证集上的首选一致率只有 16%。

```sh
.venv/Scripts/python -m az_worker.warmstart --games 120 --model models/az/warmstart.pt
```

### 6.1 预热之后哪里还是弱的（2026-11-16 实测）

按上面那份配方跑一遍（300 局 / 0.1 秒 / 2000 步）：

| 指标 | 数值 |
| --- | --- |
| 样本 | 7516 训练 + 835 验证 |
| 价值范围 | −1.000 到 1.000 |
| **验证首选一致率** | **59 %**（老师的第一手被原样选中） |

网络确实学到了棋型。把同一个网络直接问一个战术局面（黑棋 (7,7)-(7,10) 连四，
黑走）：

| 头 | 输出 | 应该是 |
| --- | --- | --- |
| 策略头 | (7,6) 0.81、(7,11) 0.18 —— 赢点排第一 | 对 |
| 价值头 | **−0.234** | 正数（黑棋马上赢了） |

**策略头学到了，价值头没有。** 价值头只见过整局结果（±1），它能判断「这盘谁
赢」，判断不了「现在有多好」——它甚至在一个必胜局面里给出负数。

那这是不是「0 胜 10 负」的原因？**不是。** 把价值从搜索里整个拿掉（网络照旧，
只是叶子估值恒为 0，PUCT 只剩先验项）再打 24 局：

| 配置 | 对传统引擎（深度 4） |
| --- | --- |
| 原始网络（带价值） | 0 胜 24 负 |
| 只留先验（价值 = 0） | 1 胜 23 负 |

一个胜局之差，在 24 局里是噪声。**价值头坏了是真的，但去掉它并不改变结局**，
所以它不是决定性的那一环。

真正决定胜负的是另外两件事：

1. **网络只有 59 % 的概率原样选中老师的第一手。** 传统引擎每手都是它最好的一
   着；网络有四成的时候在走次优解，而搜索的 200 次模拟不足以把次优解纠正回来。
2. **搜索的分辨率不够。** 200 次访问摊到二十来个候选点上，分不出「好」和「很
   好」；传统引擎一次深度 4 的完整搜索直接看到具体局面。

所以下一步不是修价值头，也不是更多训练，而是提高**每手的选择质量**：要么让
网络更贴近老师（更长的预热、更强的老师），要么让搜索看得更细（更多模拟、更强
的先验剪枝）。价值头要修，但它是第二顺位。

预热之后回到自对弈：

```sh
.venv/Scripts/python -m az_worker.train --model models/az/warmstart.pt --games 10 --iterations 50
```

**预热不是 AlphaZero 的一部分**，它是这个仓库特有的启动手段：把已有的棋型知识
灌进网络，让自对弈从一个已经会下的网络开始。没有这一步，纯自对弈在这个规模上
学不出来。

## 7. 自对弈与训练

### 7.1 一个样本

自对弈的每一手产生一个样本：

| 字段 | 内容 |
| --- | --- |
| `planes` | 该局面的三个平面 |
| `policy` | 这次搜索的访问次数分布（归一化） |
| `legal` | 合法格子的掩码 |
| `value` | 整局结果，从该局面轮到走棋的一方看：胜 1、负 −1、和 0 |

策略目标就是搜索自己给出的分布——这就是「用搜索改进搜索」的那一步。

### 7.2 训练循环

```
每轮：
  1. 用当前网络自对弈 N 局（棋谱进回放缓冲区，容量 60 000）
  2. 从缓冲区随机取 batch（默认 256），训练 M 步
  3. 存权重
```

损失：

```
policy_loss = −Σ π · log_softmax(logits)      # 只在合法格子上
value_loss  = (v − z)²
loss        = policy_loss + value_loss
```

两个细节：

- **策略目标先按掩码重新归一化**。否则一个落在非法格子上的权重会乘上 −1e9 的
  对数概率，直接把损失顶成天文数字，梯度变成 NaN。
- **非法格子的 logits 用 −1e9 而不是 −inf**。`−inf` 在 `log_softmax` 里产生
  `-inf × 0 = NaN`。

每轮还会额外下**一局不参与训练**的对局，用它算验证损失。训练损失下降不等于
学会了：网络有两百万参数，几千个样本就能把它背下来，验证损失才是真的。

### 7.3 采样温度

前 12 手用温度 1（按访问次数采样，多样性），之后温度 0（只走访问最多的招）。
根节点还加了 Dirichlet 噪声（α = 0.3，权重 0.25），这是 AlphaZero 原版的做法，
用来保证同一局面也有不同的着法可试。

### 7.4 命令行

```sh
.venv/Scripts/python -m az_worker.train \
  --games 10 --iterations 10 --simulations 200 \
  --channels 64 --blocks 6 --device cuda \
  --model models/az/current.pt
```

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--games` | 10 | 每轮自对弈局数 |
| `--iterations` | 10 | 训练轮数 |
| `--simulations` | 200 | 每手搜索模拟次数 |
| `--train-steps` | 300 | 每轮训练步数 |
| `--batch-size` | 256 | 训练批大小 |
| `--buffer` | 60000 | 回放缓冲区容量 |
| `--channels` / `--blocks` | 64 / 6 | 网络宽度与深度 |
| `--lr` | 1e-3 | 学习率 |
| `--temperature-moves` | 12 | 前多少手用温度采样 |
| `--c-puct` | 1.5 | PUCT 常数 |
| `--candidate-radius` | 1 | 候选点半径 |
| `--device` | auto | 计算设备 |
| `--model` | models/az/current.pt | 权重文件 |
| `--no-augment` | 关 | 不做对称增强 |

## 8. 对局

```sh
.venv/Scripts/python -m az_worker
```

引擎在 `configs/engines.json` 里注册（`engine_id` 用 `az`）。MyGo 启动后会把令牌
写进 `configs/engines.runtime.json`，worker 自己读，不需要手工复制。

```json
{
  "engine_id": "az",
  "display_name": "AlphaZero AI",
  "token": "随便一个随机串",
  "available": true
}
```

参数写在 `az_worker/.env`（模板 `.env.example`）：`AZ_MODEL_PATH`、`AZ_DEVICE`、
`AZ_SIMULATIONS`、`AZ_C_PUCT`、`AZ_BATCH_SIZE`、`AZ_CANDIDATE_RADIUS`、
`AZ_TEMPERATURE`。

对局的 `config` 可以覆盖 `simulations` 和 `temperature`，不需要重启 worker。

## 9. 擂台赛

```sh
.venv/Scripts/python -m az_worker.arena --games 20 --device cuda
```

AlphaZero 与传统引擎（`classical_worker`，深度 4 / 0.5 秒）交替执黑，报告胜平负。
这是判断「训练有没有用」的唯一可靠指标——训练损失下降不等于棋力上升。

### 本机的实测

| 配置 | 对传统引擎 |
| --- | --- |
| 纯自对弈 240 局（无预热） | 0 胜 10 负 |
| 预热后（网络首选与老师一致 50%） | 0 胜 10 负 |
| 预热后（首选与老师一致 59%，200 次模拟） | 0 胜 10 负 |
| 同上，400 次模拟 | 0 胜 10 负 |
| 同上，但搜索里没有价值（只留先验） | 1 胜 23 负 |
| **MCTS + 传统引擎的策略与价值（oracle）** | **1 胜 5 负** |

最后一行是重点：把网络整个换掉，换成传统引擎自己的策略与价值，AlphaZero 的
搜索**仍然打不过传统引擎本身**。所以差距不在网络，而在搜索：

- 传统引擎每手搜到深度 4 的**具体局面**，还带 VCF（连续冲四）这种针对性的必胜
  搜索；
- AlphaZero 的 MCTS 靠**访问次数**表达「这手更好」，200 次模拟分到 20 个候选点
  上，区分度远不如一次深度 4 的完整搜索。

**结论：在这个棋盘大小上，纯 AlphaZero 的 MCTS 打不过带 VCF 的传统引擎。**这不是
调参能解决的，是搜索结构的差距。AlphaZero 在围棋上能赢，是因为围棋的分支因子
和深度都大得多，访问次数的分辨率够用。

因此这个引擎在本仓库里的定位是：

1. **可运行、可训练、可对局的第三个引擎**——协议、训练、评估、擂台赛都齐了；
2. **学习 AlphaZero 的实验台**，不是最强的棋手；
3. 要让它真的强，需要的不是更多训练，而是更快的搜索（GPU 上跑批量的 MCTS，
   或者把传统引擎的 VCF 作为搜索的一个分支）。

第 3 条是这个引擎下一步该做的事，本设计没有实现它。

## 10. 已知限制

| 限制 | 后果 | 缓解 |
| --- | --- | --- |
| 纯自对弈起步慢 | 前几百轮网络很弱 | 用传统引擎预热（第 6 节） |
| 搜索是串行的 | 模拟次数受 Python 速度限制 | 批量评估把 GPU 吃满；提高 `--simulations` |
| 候选点半径 1 | 隔两格的战术看不到 | `--candidate-radius` 可调，但分布会变平 |
| 没有弃权 | 必败的局会下满 | 网络的价值头学会快认输需要更多训练 |
| 单进程自对弈 | 数据生成是瓶颈 | 并行自对弈留作后续 |
| 预热数据来自传统引擎 | 网络的上限被老师的水平限制 | 自对弈阶段摆脱这个限制 |
| 兜底规则只管一手成五 | 活三、冲四要靠网络自己看出来 | 预热把老师的堵法学进网络；训练不足时这一步最容易输 |

### 指标要小心

「验证首选一致率」这个指标很容易骗人。**必须算网络的首选是否正好是老师的第一
手**，而不是「网络的首选是不是也在老师考虑过的着法里」——后者在老师给出八个
候选时几乎必然成立，看起来有 88%，其实只有 38%。

同样，训练损失下降不等于学会：网络有两百万参数，几千个样本就能把它背下来。训
练损失 0.16 而验证损失 2.17 的组合，意思是它把训练集背下来了。

## 11. 与传统引擎的关系

两个引擎共用 `aiworker/` 协议，各管「下哪里」。传统引擎是确定性的、可解释的、
秒级出招；AlphaZero 是学出来的、需要训练、依赖显卡。

并存的意义：传统引擎是 AlphaZero 的**基线**——擂台赛的对手，也是训练早期网络
（还没学会基本棋型时）的陪练。
