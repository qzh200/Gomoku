# 0001 三套机制各司其职

**状态**：已接受

## 背景

AI Worker 通过长轮询领取回合并提交落子。重复领取、过期落子与重复提交是三类不同的
失败，业界常见的做法是用一个机制覆盖全部，但它们的失效表现并不相同。

## 决策

* **任务租约** 解决「同一个回合被重复领取」。失效表现是 `CLAIM_EXPIRED` /
  `CLAIM_INVALID`。
* **棋局版本** 解决「过期结果写入棋盘」。失效表现是 `VERSION_CONFLICT`。
* **幂等键** 解决「同一个请求被重复提交」。失效表现是返回首次保存的结果，或
  `IDEMPOTENCY_KEY_REUSED`。

三者同时存在，任何一个都不能替代另外两个。

## 后果

落子路径需要三处独立检查：租约表、棋局版本、幂等表。代价是一次落子要访问三处
状态，收益是每种失败都有明确且可诊断的错误码，Worker 也能据此决定是丢弃结果、
重新计算还是释放租约。
