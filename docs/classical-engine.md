# 传统算法引擎（第二代：威胁搜索 + PVS + 置换表）

`classical_worker/` 是 `classical` 引擎的实现：不看模型的传统搜索，够快、可复现、
不花钱。它按 [`docs/ai-protocol.md`](ai-protocol.md) 的长轮询协议领任务，和 LLM
引擎共用同一套 Worker 协议。

设计决策与分阶段验收见 [`classical-engine-v2.md`](classical-engine-v2.md)。

## 1. 结构

```
aiworker/          两个引擎共用：领任务、续租约、提交落子、参数与令牌
classical_worker/
  patterns.py      6 格窗口表：成五、活四、冲四、活三……
  position.py      棋盘、窗口增量分、Zobrist 哈希、落子/撤销
  threats.py       威胁分类、强制着、VCF/VCT
  tt.py            置换表、将杀分归一化
  search.py        迭代加深 PVS、杀手着法、历史启发、时间管理
  engine.py        把一次任务变成一手棋
  config.py        搜索参数（.env）
  benchmark.py     对冻结的第一代做自对弈基准（仅开发用）
```

`aiworker/` 里没有棋，`classical_worker/` 里没有网络：引擎只回答"下哪里"。

| 模块 | 职责 | 不做什么 |
| --- | --- | --- |
| `aiworker.protocol` | 领任务、租约、提交、退避 | 不懂棋 |
| `aiworker.settings` | .env、令牌、连接参数 | 不懂搜索 |
| `patterns` | 窗口编码与棋型分 | 不碰棋盘 |
| `position` | 棋盘、增量分、哈希、落子/撤销 | 不做搜索 |
| `threats` | 威胁等级、强制着、VCF/VCT | 不碰网络 |
| `tt` | 局面哈希到搜索结论 | 不懂棋 |
| `search` | 迭代加深、PVS、时间预算 | 不碰网络 |
| `engine` | 组装一次搜索 | 不管协议 |

## 2. 评估：6 格窗口

每条线（横、竖、两条斜线）按 6 格滑窗切成窗口。窗口内的格子编码为 3 进制
（空 0、自己 1、对方 2），共 729 种；导入时建一张表，查表得到黑白双方的分值。

| 棋型 | 命中示例（己方=1，空=0，阻挡=2） | 分值 |
| --- | --- | --- |
| 成五 | `11111` | 10,000,000 |
| 活四 | `011110` | 120,000 |
| 冲四 | `011112`、`211110`、`11011`、`10111`、`11101` | 15,000 |
| 活三 | `011100`、`001110`、`010110`、`011010` | 6,000 |
| 眠三 | `001112`、`211100` | 600 |
| 活二 | `001100`、`010100` | 300 |
| 眠二 | `001120`、`021100` | 50 |
| 单子 | `001000` | 2 |

- 每个窗口只认最高棋型；重叠窗口会重复计入同一段连子，分值只用于比较；
- 落子只改动穿过该点的 4 条线，每条线最多 6 个窗口，所以一次落子最多更新
  24 个窗口；撤销用同一批编码反算，不重扫棋盘；
- 取分是 `totals[自己] - totals[对方]`，O(1)。

## 3. 威胁与强制着

对候选点，构造穿过它的 4 条 9 格线（该点视为己方），查表得到：

- 是否成五；
- 成五点数量（1 = 冲四，≥2 = 双四/活四，对手堵不完）；
- 活四点数量（能形成活四的空点，即活三的延伸点）。

排序等级：成五 > 双四/活四 > 四三 > 双三 > 冲四 > 活三。每个节点的候选点按
「攻击等级、防守等级、杀手着法、历史启发」排序，前 `CLASSICAL_WIDTH` 个进入搜索。

强制着在排序前收敛分支：

1. 己方能成五 → 只走成五点；
2. 对手只有**一个**成五点 → 只走该点；
3. 对手有两个成五点 → 堵不完；先试己方 VCF，找不到就返回最不坏的堵点。

## 4. 搜索：迭代加深 + PVS + 置换表

- negamax 的每个节点回答"轮到我走，这局面值多少"，回溯时取负；
- 第一个子节点用全窗口，其余用零窗口，超过 alpha 再全窗口重搜；
- 深度从 2 开始逐层加深；每层完整搜完才替换着法，超时保留上一层结论；
- 胜利用 `MATE_SCORE - ply`，越早赢分越高；
- **不做 LMR**：五子棋的安静着法可能就是唯一防守点，削减层数会漏反杀；
- 置换表用固定种子的 Zobrist 哈希，键包含轮次；表项有深度、值、上下界、最佳着法
  与时代；将杀分按当前 `ply` 归一化后入库；表随进程存活，跨手复用；
- 每 64 个节点检查一次硬截止；`play`/`undo` 都在 `finally` 里配对，超时不会污染
  棋盘。

## 5. VCF 与 VCT

- **VCF（连续冲四）**：只走能形成四或五的着法，对手被强制堵唯一的成五点；一着
  形成两个成五点即胜。根节点运行，默认占 10% 预算，找到必胜立即落子。VCF 内部
  会检查对手的成五，所以不会漏掉"对手先赢"。
- **VCT（连续威胁）**：在四之外允许活三；防守方被假定为堵成五点或活四点。当前
  实现是根节点近似，**不生成防守方的反四**，自对弈中开启会降低胜率，因此默认
  关闭（`CLASSICAL_VCT_BUDGET=0.0`）。代码与单测保留，需要时再打开。

## 6. 参数

```sh
cp classical_worker/.env.example classical_worker/.env
```

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `MYGO_URL` | 否 | `http://127.0.0.1:8080/api/v1` | MyGo API 根地址 |
| `MYGO_ENGINE_TOKEN` | 否 | 自动获取 | 留空则读 MyGo 写的 `configs/engines.runtime.json` |
| `MYGO_ENGINE_ID` | 否 | `classical` | 引擎标识 |
| `MYGO_WORKER_ID` | 否 | `classical-worker-01` | 日志标识 |
| `MYGO_WAIT_SECONDS` | 否 | `20` | 长轮询等待秒数 |
| `MYGO_LEASE_EXTEND_SECONDS` | 否 | `120` | 租约续期长度 |
| `CLASSICAL_DEPTH` | 否 | `8` | 最大搜索深度（层） |
| `CLASSICAL_WIDTH` | 否 | `12` | 每层候选点数 |
| `CLASSICAL_TIME_BUDGET` | 否 | `2.0` | 单手时间上限 |
| `CLASSICAL_VCF_BUDGET` | 否 | `0.10` | VCF 占总预算的比例，0 关闭 |
| `CLASSICAL_VCT_BUDGET` | 否 | `0.0` | VCT 占总预算的比例，默认关闭 |
| `CLASSICAL_TT_ENTRIES` | 否 | `200000` | 置换表条目上限 |

开局时 MyGo 也可以按对局覆盖参数，例如创建棋局时给 `classical` 侧
`{"config": {"depth": 3}}`；对局参数优先于 .env。

## 7. 运行

```sh
go run ./cmd/app            # 先起 MyGo，它写令牌
python -m classical_worker
```

桌面界面里选「AI 对战」，先手或后手选 `Classical AI`。

## 8. 测试

```sh
python -m unittest discover -s classical_worker/tests -t .
go test ./tests/contracts/ -run TestClassicalWorkerFinishesAGame
```

- 单元测试覆盖：窗口棋型表与黑白对称、增量总分等于全量重算、哈希复原、威胁
  分类、强制着、PVS+TT 的值等于不剪枝 negamax、置换表复用、VCF、VCT 的边界、
  超时后棋盘干净；
- 契约测试用两个真实进程（分别持 `classical` 与 `llm` 令牌）打完一整局真实 HTTP
  对局。

## 9. 棋力与限制

基准：冻结的第一代引擎放在 `classical_worker/tests/fixtures/`，用
`python -m classical_worker.benchmark --games 20 --budget 0.2` 对弈 20 局、
先后手各半、固定开局表。结果：14 胜 6 负，平均 0.126 秒，p95 0.204 秒，
完成深度平均 2.2 层。

已知限制：

- Python 单线程下节点成本偏高；0.2 秒预算通常只到 2–3 层，深算靠 2 秒默认预算；
- 窗口分对重叠窗口重复计分，权重靠基准校准，不追求单窗口语义；
- VCT 的防守不生成反四，默认关闭；
- 没有开局库与禁手规则（与协议一致：第一版无禁手）。
